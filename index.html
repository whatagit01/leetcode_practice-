        New to Big-O? Read the 2-minute guide
        

          
Big-O describes how the work grows as the input grows. It ignores small details like how fast your computer is, and asks: if the input gets 10× bigger, how much more work is there? n is the size of the input, such as the length of the list.

Space is the extra memory the algorithm needs, beyond the input it was given. A few variables is O(1). A set or dict that remembers every item you've seen is O(n). The answer you return usually isn't counted. Recursion uses memory too: every call that hasn't finished yet waits on the call stack.

          
The usual trade-off: brute force is slow but light on memory. Checking every pair with two loops needs only the two loop counters, so it's O(1) space, but O(n²) time. Faster approaches often spend memory to save time: Two Sum's hash map remembers every number (O(n) space) so it never has to look back (O(n) time). The best answers find a trick that's fast and small, like two pointers.

          
Other letters: k, m are other sizes (window length, second list). h is a tree's height, w its widest level. V and E are a graph's nodes and edges. Amortised means "averaged over many calls": an occasional slow step is paid for by many fast ones.
